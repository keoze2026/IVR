1. SUMMARY
--------------------------------------------------------------------------------

Week 1 was the data model and the compliance layer. Week 2 was the call path -
and, more importantly, proving it against a real carrier rather than against
test doubles.

The headline: an outbound call was placed, answered, traversed the IVR, captured
a keypress, recorded an opt-out, and released its channel. That path is now
evidenced end to end rather than assumed.

Two defects were found in the process. Both were invisible to the test suite and
both would have been serious in production - one of them would have silently
broken every call. Details in section 4. That is the argument for doing carrier
testing before launch rather than after, and it is the main reason this week was
worth spending on integration rather than new features.

Completed this week:

    roles, beat scheduler.

Rough completion against the spec as a whole: I would call it 85-90%. What

       Callback ingest     80/sec sustained, all accepted, mean latency 120ms
       Callback ceiling    saturates at ~95/sec on one process

     The limiters are nowhere near being the bottleneck. The callback ingest
     ceiling is the number to plan capacity against.

3.3  External suppression (DNC) loading

     Previously an unimplemented integration point. The vendor-specific parts -
     which registry, whose credential, how often - remain configuration, because
     they differ per contract. What every source has in common is that it ends
     in a file of phone numbers, and that part is now implemented and tested:
     CSV, plain text, zip archives, headerless files, and the byte-order marks
     that appear in vendor exports.

     Configure one of:
       SCRUB_SOURCE_DIR   directory the vendor's own downloader writes into
                          (preferred - no credential held in this codebase)
       SCRUB_SOURCE_URL   HTTPS URL with an optional bearer token

     With neither set the job still fails loudly and records the failure, so
     "when did you last scrub?" keeps an honest answer rather than reporting a
     successful scrub of nothing.

     The parser refuses to guess on ambiguous input. The two failure directions
     are not symmetric: a missed number means calling somebody who opted out,
     but an invented one silently suppresses a customer who never asked to be,
     and nothing downstream ever flags it. 31 tests cover both directions.

4. DEFECTS FOUND AND FIXED
--------------------------------------------------------------------------------

4.1  Webhook signature verification dropped blank parameters   [SERIOUS]

     Callback bodies were parsed with a function whose default behaviour
     silently discards any parameter with an empty value. The carrier signs
     over every parameter it sends, and real callbacks carry several blanks -
     CalledCity, CalledState and CallerName are all empty for an international
     destination.

     The verifier therefore rebuilt a different string than the carrier had
     signed, and every live webhook was rejected with a 403. In production that
     means no call statuses, no DTMF, and - most seriously - no opt-outs would
     ever have been recorded, while the application logged nothing more
     alarming than a rejected signature.

     Every test in the suite passed throughout, because hand-built test
     payloads contain no empty fields. Fixed, with a regression test that fails
     when the bug is reintroduced. Confirmed afterwards against the live
     carrier: 8 callbacks, all accepted.

     This is the defect that justifies the whole week. It is not reachable
     without a real carrier.

4.2  Scrub job counters reported the wrong quantity

     The suppression routine returned the number of contacts flagged, which the
     job then stored in the field meaning "suppression entries added", while
     the contacts field was never written at all.

     Those are different quantities. A scrub can add fifty thousand entries and
     match none of your contacts, which means it worked. As written, a healthy
     scrub looked like a broken one. Both counts are now reported separately,
     and derived from an explicit index lookup rather than from a bulk-insert
     return value, which is unusable for counting on PostgreSQL.

4.3  Lost-callback recovery took 90 minutes

     Not a defect exactly, but a default worth revisiting. When callbacks are
     lost, each affected call holds a channel until a sweep asks the carrier
     what happened - and that sweep only considered calls older than 90
     minutes. An ingress outage loses every callback at once, so a campaign
     would stall for an hour and a half with no error surfaced anywhere.
     Observed directly during testing. Now configurable, defaulting to 15
     minutes.

6. BLOCKERS AND DEPENDENCIES
--------------------------------------------------------------------------------

6.1  Federal DNC registration - ON THE CRITICAL PATH

     This is now the single hard blocker to dialling US numbers, and it is
     procurement rather than engineering. The loading code is implemented and
     tested; it needs a subscription account number and a source to read from.

     Registration is at telemarketing.donotcall.gov. There is a waiting period,
     which is why this should start immediately regardless of where the rest of
     the work stands. Please confirm who is opening the account and against
     which entity.

6.2  State calling-hour restrictions - NEEDS LEGAL REVIEW

     Every call currently defaults to the federal 08:00-21:00 ceiling. That is
     safe but not correct: several states are stricter. Configuring per-state
     windows requires the official NANPA dataset and a legal review of the
     rules themselves. A wrong entry in a shipped table is worse than no entry,
     because it reads as authoritative.

6.3  Caller ID attestation is C

     Observed during preflight on the test caller ID. US carriers are
     substantially more likely to label or block calls below full attestation.
     This is a carrier and number-provisioning question rather than a code one,
     but it will affect answer rates materially and is worth resolving before
     any volume.


--------------------------------------------------------------------------------
7. DECISIONS REQUESTED
--------------------------------------------------------------------------------

  1. DNC source. Direct federal registration, or a compliance aggregator that
     bundles the federal registry, state registries and litigator lists behind
     one interface? Direct is cheaper; an aggregator removes three separate
     integrations and the "did anyone renew the state subscription" problem.

  2. Object storage. Prompt pre-rendering and call recording both need an
     S3-compatible bucket. Any S3-compatible endpoint works, including
     self-hosted. Needed before recording can be offered at all.

  3. Default campaign calling window. The current default is 09:00-17:00 local,
     which is narrower than the law requires and cuts off legitimate evening
     calling. Confirm the intended default before campaigns are created against
     it.
